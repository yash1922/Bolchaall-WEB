# Bolchall V2 — Deploy guide (Vercel + Render)

This guide walks you through deploying Bolchall to free hosting tiers so testers can use it from anywhere.

**Stack:**
- **Web** (Next.js) → Vercel (free hobby tier)
- **API** (Express + Socket.io) → Render (free tier, sleeps after 15 min idle)
- **Database** → MongoDB Atlas (already set up)

**Time:** 15–25 minutes for the first deploy.

---

## 0. Prerequisites

- Repo pushed to GitHub (`yash1922/Bolchaall-WEB`).
- A MongoDB Atlas cluster with a database user and IP allowlist set to `0.0.0.0/0` (or specifically the Render egress range).
- A Vercel account (sign up at https://vercel.com — use your GitHub login).
- A Render account (sign up at https://render.com — use your GitHub login).

Generate two strong JWT secrets up-front (you'll paste them into Render):
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## 1. Deploy the API to Render

The repo includes `render.yaml` at the root — Render will detect it.

1. Go to https://dashboard.render.com/select-repo?type=blueprint
2. Connect your GitHub account if you haven't already.
3. Pick the `Bolchaall-WEB` repo. Render reads `render.yaml` and shows you the `bolchall-api` service.
4. Click **Apply** to provision.
5. Wait for the first deploy to start (~3 min). It will fail or report missing env vars.
6. Go to the **`bolchall-api`** service → **Environment** tab → fill in:
   - `MONGODB_URI` → your full Atlas connection string, e.g. `mongodb+srv://user:pass@cluster0.xxxx.mongodb.net/bolchall?retryWrites=true&w=majority`
   - `WEB_ORIGIN` → leave blank for now; you'll fill it in **after** Vercel deploys (Step 2)
   - `PUBLIC_API_URL` → the URL Render assigns this service, e.g. `https://bolchall-api.onrender.com` (visible at the top of the service page)
   - `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` → already auto-generated by Render — leave them
   - Leave `STRIPE_*`, `CLOUDINARY_*`, `RESEND_API_KEY` blank (we'll wire Stripe later; the others have console fallbacks)
   - `BOLCHALL_INCLUDE_DEMO_USERS` → set to `false` (no demo accounts in production)
7. Save changes — Render redeploys automatically.
8. Once status is **Live**, copy the URL (e.g. `https://bolchall-api.onrender.com`).
9. Visit `<api-url>/api/health` in your browser → should return `{"ok":true,"service":"bolchall-api",...}`.

**Bootstrap the first admin** (one-time, via Render Shell):
1. In the Render dashboard, click **Shell** for `bolchall-api`.
2. Run:
   ```bash
   pnpm create-admin admin@yourdomain.com "Your Name" "your-strong-password"
   ```

## 2. Deploy the Web to Vercel

The repo includes `web/vercel.json` configured for the pnpm monorepo.

1. Go to https://vercel.com/new → **Import Git Repository** → pick `Bolchaall-WEB`.
2. **IMPORTANT** in the Vercel project settings:
   - **Root Directory:** click **Edit** and set to `web` (this tells Vercel that's where your Next.js app lives)
   - **Framework Preset:** Next.js (should auto-detect)
   - **Build Command, Install Command, Output Directory:** leave as defaults — `vercel.json` overrides them
3. Click **Environment Variables** and add:
   - `NEXT_PUBLIC_API_URL` → the Render API URL from Step 1 (e.g. `https://bolchall-api.onrender.com`)
   - `NEXT_PUBLIC_SOCKET_URL` → same as `NEXT_PUBLIC_API_URL`
4. Click **Deploy**.
5. First deploy takes 2–4 min. When it's live, you'll get a URL like `https://bolchaall-web.vercel.app`.
6. Visit it — the landing page should render. Login won't work yet because the API doesn't allow this origin (next step).

---

## 3. Connect them (CORS)

1. Go back to the **Render** dashboard → `bolchall-api` → **Environment** tab.
2. Set `WEB_ORIGIN` to your Vercel URL: `https://bolchaall-web.vercel.app`
   - If you'll use multiple domains, comma-separate them: `https://bolchaall-web.vercel.app,https://app.bolchall.com`
   - Wildcard subdomain support: `https://*.vercel.app` (works for Vercel preview deploys)
3. Save → Render redeploys (~30 sec).
4. Refresh your Vercel URL → log in with the admin account you created in Step 1's Shell.

## 4. (Optional) Set up Cloudinary for file uploads

The doctor onboarding form uploads license/ID documents. Without Cloudinary keys, files are stored as base64 in MongoDB (capped at 2 MB each — fine for low volume).

To enable proper Cloudinary:
1. Sign up at https://cloudinary.com (free tier: 25 GB storage).
2. Find your cloud name + API key + secret in the Dashboard.
3. In Render, set `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
4. Restart.

(Implementation note: the current code only writes the base64 fallback path; full Cloudinary signed-upload wiring is not yet enabled. The base64 fallback is fine for testing.)

---

## 5. (Optional) Set up Resend for emails

Without `RESEND_API_KEY`, all transactional emails (welcome, doctor approval/rejection, assignment notifications) log to the API console instead of being sent.

To enable:
1. Sign up at https://resend.com (free tier: 100 emails/day).
2. Add and verify your sending domain.
3. In Render, set `RESEND_API_KEY` and update `RESEND_FROM` to a verified address.

---

## 6. Custom domain (later)

Both Vercel (web) and Render (api) accept custom domains via DNS:
- Web: `app.bolchall.com` → Vercel
- API: `api.bolchall.com` → Render
- Update `WEB_ORIGIN` (in Render) and `NEXT_PUBLIC_API_URL` (in Vercel) when you switch domains.

## 7. Common gotchas

| Symptom | Likely cause | Fix |
|---|---|---|
| `Failed to fetch` on login | Render service is asleep (free tier) or `NEXT_PUBLIC_API_URL` wrong | Wait ~30s for Render cold-start; double-check the env var |
| `CORS: origin … not allowed` | `WEB_ORIGIN` doesn't include the Vercel URL | Add it to the Render env (comma-separated for multiple) |
| Login works once then fails on refresh | Cookies blocked because api/web are on different domains and `secure` is required | This works automatically over HTTPS once both are deployed; only fails on http |
| `MONGODB_URI not set` | Mongo URI missing in Render | Add it in **Environment** tab; service will redeploy |
| Web build fails on Vercel | Root Directory not set to `web` | Project settings → General → Root Directory → `web` |
| Socket.io chat doesn't connect | `NEXT_PUBLIC_SOCKET_URL` wrong or Render cold | Same as login fetch issue; ensure URL matches your Render service |

## 8. Updating the deploy

After this initial setup, every push to `main` on GitHub auto-deploys to BOTH Vercel and Render. To deploy fixes:

```bash
# from your local machine
git add -A
git commit -m "fix: ..."
git push origin main
```

Vercel + Render both watch the repo and rebuild within 1–2 minutes.
